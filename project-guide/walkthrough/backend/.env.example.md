# backend/.env.example

## 1. Purpose
A template for the real `backend/.env` file. A `.env` file is a plain text list of `NAME=value` lines that sets **environment variables** (settings the program reads from outside the code. *Example:* `DATABASE_URL`). You copy this file to `.env` and put real values in it. The real `.env` must never be committed. The backend reads these through `get_settings()` in `backend/app/core/config.py`.

## 2. Imports, one by one
Not applicable: this is not code. Lines starting with `#` are comments.

## 3. Walk through the file (line by line)
- Line 1 `ENVIRONMENT=development`: which mode the app runs in. Production should use another value (check `config.py` for the exact allowed names).
- Line 2 `DATABASE_URL=sqlite:///...`: where the database is. `sqlite:///` means a single file database. The path is a Windows example (`C:/...`). On Arch Linux use something like `sqlite:///./cabapp.db`.
- Line 3 `AUTO_MIGRATE=true`: probably runs Alembic migrations when the server starts. I am not sure; check with `rg -n AUTO_MIGRATE backend/app`.
- Line 4 comment: a production example with **PostgreSQL**: `postgresql+psycopg://user:password@host:5432/dbname`. `psycopg` is the Python driver. The password here is the placeholder `CHANGE_ME`.
- Line 5 `JWT_SECRET_KEY=<secret>`: the key that signs login tokens. **JWT** = JSON Web Token (a signed string that proves who the user is). If someone learns this key they can forge logins. Use a long random value, for example `openssl rand -hex 32`.
- Line 6 `FIREBASE_CREDENTIALS_PATH`: path to a Firebase service-account JSON file (Firebase is Google's service, probably used here for phone login or push notifications; check the code). The file itself is secret.
- Line 7 comment and lines 8-11 `ADMIN_BOOTSTRAP_EMAIL`, `ADMIN_BOOTSTRAP_PASSWORD=<secret>`, `ADMIN_BOOTSTRAP_NAME`, `ADMIN_BOOTSTRAP_ROLE=super_admin`: create the first admin account at startup. After that, change the password.
- Line 12 `GEOAPIFY_API_KEY=<secret>`: key for `map_provider_service.py:113`. Without it map routes return 503.
- Line 13 `MAPS_CONTACT_EMAIL=<contact-email>`: sent in the User-Agent header to the map service (`map_provider_service.py:91`). The file contains a real looking personal email; replace it with your own.

## 4. How data flows
```
.env file -> pydantic settings (config.py) -> get_settings() -> services (e.g. MapProviderService._key)
```

## 5. Try it
```
cd backend && cp .env.example .env
```
`cp A B` copies file A to B. Then edit `.env` with your editor. Expected: no output; a new `.env` appears. Check that git ignores it: `git check-ignore backend/.env` prints the path if ignored.

## 6. Can it be better?
- Good: includes comments, placeholders and a production database example.
- Weak: Windows-only path examples; one personal email left in an example file; no comment for each variable; `AUTO_MIGRATE=true` as a default can be risky in production.
- Cleaner: use `DATABASE_URL=sqlite:///./cabapp.db` and put a short comment above every key.
- Security: never commit `.env`; rotate the Geoapify key if it was ever committed; the admin password placeholder must be changed.
