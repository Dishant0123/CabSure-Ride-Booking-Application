# passenger-app/.env.example

## 1. Purpose
A `.env` file holds settings that change per machine (addresses, timeouts). This `.env.example` is a safe template that is committed to git. You copy it to `.env` (which is not committed). The library `react-native-config` (listed in `driver-app/package.json:32`; the passenger app likely has it too) reads `.env` at build time and gives the values to the JavaScript code. The Gradle line `apply from: ... dotenv.gradle` (`passenger-app/android/app/build.gradle:5`) is what loads it on Android.

## 2. Imports, one by one
No imports. The format is `NAME=value`, one per line. Lines that start with `#` are comments.

## 3. Walk through the code, top to bottom
- Lines 1-2: comments. In the Android emulator, `localhost` means the phone itself. The special address `10.0.2.2` reaches the computer that runs the emulator. On a real phone, use the computer's LAN IP (*Example:* `192.168.1.20`).
- `API_BASE_URL=http://10.0.2.2:8000` (line 3). Base address of the FastAPI backend (port 8000). Used by the Axios client.
- `API_TIMEOUT_MS=10000` (line 4). Wait up to 10000 milliseconds (10 seconds) for an HTTP answer.
- `WS_BASE_URL=ws://10.0.2.2:8000` (line 5). WebSocket address (a long-lived two-way connection for live updates such as driver location). `ws://` is the plain version; `wss://` is the encrypted one.
- `FIREBASE_PROJECT_ID=replace_with_your_project_id` (line 6). A placeholder. Put your Firebase project id there. It is not a secret key, but do not commit real project files.

## 4. How data flows
```
.env.example --copy--> .env --(Gradle dotenv.gradle / react-native-config)--> BuildConfig --> Config.API_BASE_URL in JS
```

## 5. Try it
```zsh
cp passenger-app/.env.example passenger-app/.env
```
`cp A B` copies file A to B. Then edit `.env`. Rebuild the app, because values are read at build time.

## 6. Can it be better?
- Good: comments explain the emulator address.
- Weak: no variable for the Google Maps or MapLibre key (if used). `http` and `ws` are plain text, fine for development only.
- Cleaner way: add a second example for release builds with `https` and `wss`.
- Security: do not put real secrets in `.env.example`. A mobile app can always be unpacked, so never store server secrets in `.env` for the app.

## 7. Check yourself
