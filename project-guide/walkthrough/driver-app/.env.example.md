# driver-app/.env.example

## 1. Purpose
A template for the driver app's settings file `.env`. You copy it to `.env` and fill the values. The app reads them through `react-native-config` (see `driver-app/android/app/build.gradle:5`). The `.example` file is safe to commit because it has no real secrets.

## 2. Imports, one by one
None.

## 3. Walk through the file
An **environment variable** is a named setting outside the code. Format: `NAME=value`.
- `API_BASE_URL=http://10.0.2.2:8000/api/v1` (`driver-app/.env.example:1`). The address of the backend REST API. `10.0.2.2` is the special address the Android emulator uses to mean "the host computer's localhost". `8000` is the FastAPI port. `/api/v1` is the API version prefix. A real phone cannot use `10.0.2.2`; use your computer's LAN IP.
- `WS_BASE_URL=ws://10.0.2.2:8000` (line 2). Address for **WebSocket** (a long-lived two-way connection, used for live updates such as ride requests). `ws://` is the plain version; production should use `wss://`.
- `FIREBASE_PROJECT_ID=replace_with_your_project_id` (line 3). Your Firebase project's id. Placeholder only.

## 4. How data flows
```
.env --(react-native-config, at build time)--> app code Config.API_BASE_URL --> HTTP/WebSocket calls to backend
```

## 5. Try it
```zsh
cp driver-app/.env.example driver-app/.env
```
`cp` copies a file. Then edit `.env`. Rebuild the app after changes, because values are baked in at build time. The exact JS usage is not in this file; search with `rg Config driver-app/src`.

## 6. Can it be better?
- Good: placeholders, no secrets, emulator-friendly.
- Weak: no comment lines explaining each value or the real-device case.
- Cleaner way: add `# comment` lines above each variable.
- Security: `.env` itself must be in `.gitignore`. Anything in a mobile app's env is readable by users, so never put private keys here.
